# Relatório de implementação — IOTSSC-CURRENT-SENSOR@0.5

## 1. Recorte executado

Implementação de `CUR-046` a `CUR-054`: exemplo executável `current_sensor` no
catálogo de `IOTSSC-HW-EXAMPLES`. Nenhum comportamento, contrato público,
estado, faixa ou serialização da capability de corrente foi alterado.

## 2. Artefatos

- `examples/executable/current_sensor/example.hpp`: aplicação Arduino única, com
  guardas de build para o símbolo de pinout, o identificador da placa, o
  identificador da capability, a cadência de apresentação e a seleção exclusiva
  do perfil elétrico;
- `examples/executable/current_sensor/README.md`: objetivo, APIs, pinos,
  ligação por perfil, configurações, comandos, validação manual, resultado
  esperado e riscos;
- `src/ExecutableExampleRunner.cpp`: seletor `IOTSMARTSYS_EXAMPLE_CURRENT_SENSOR`
  incluído na exclusividade mútua vigente;
- `configs/executable_examples.ini`: environment `example_current_sensor_mcb_r1`;
- `examples/README.md`: catálogo atualizado.

## 3. Decisões locais

1. O sinal usa `ITS_MCB01_J4_EXT_ADC` (GPIO 34, ADC1), único símbolo oficial de
   entrada analógica do pinout da MCB R1; nenhum literal de GPIO foi introduzido
   no exemplo ou no environment.
2. O perfil é escolhido por `EXAMPLE_CURRENT_SENSOR_PROFILE_3V3` ou
   `EXAMPLE_CURRENT_SENSOR_PROFILE_5V`, com `#error` para zero ou dois; o
   environment versionado seleciona 3,3 V.
3. O identificador da capability (`pv-current`) e a cadência de apresentação
   (`1000 ms`) vêm do environment, evitando constantes no código do exemplo.
4. `loop()` chama `SmartSysApp::handle()` antes de qualquer apresentação, lê
   somente a última medição estável e retorna cedo quando o registro falhou.
5. A recalibração é acionada pelo caractere `c` no monitor serial, sem qualquer
   comando remoto.
6. Valores com magnitude abaixo de `0,0005 A` são apresentados como `0.000`,
   evitando `-0.000` na saída do exemplo; a normalização contratual do `value`
   da capability permanece na biblioteca.

## 4. Evidências

- `pio run -e example_current_sensor_mcb_r1`: `SUCCESS` (código 0, 25,969 s),
  RAM `81196/327680`, flash `1830513/2031616` bytes;
- `pio run -e esp32_dev`: `SUCCESS` (código 0, 26,792 s);
- `pio run -e example_basic_light_mcb_r1`: `SUCCESS` (código 0, 25,768 s),
  confirmando que o novo seletor não regride o catálogo existente;
- `nm firmware.elf`: exatamente um `_Z5setupv` e um `_Z4loopv` no firmware do
  exemplo;
- `pio project config --json-output`: resolução aprovada;
- `git diff --check`: aprovado;
- inspeção: ausência de literais de GPIO, de macros próprias de pino, de
  redefinição de símbolos do pinout e de indicadores de segredo no recorte.

## 5. Limitações

- `CUR-AC-017` e as demais validações físicas permanecem `Not Executed`: upload,
  monitor e hardware não foram autorizados nesta atuação;
- a exclusividade do perfil e as demais guardas de build foram verificadas por
  inspeção do pré-processador, não por builds negativos dedicados;
- o exemplo não monitora alimentação, portanto `NOT_MONITORED` é o único estado
  observável e a exatidão contratada não é afirmada;
- nenhum teste automatizado foi criado ou executado, conforme `CUR-DEC-009`.
